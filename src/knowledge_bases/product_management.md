## CORE PM FRAMEWORKS

### Jobs to Be Done (JTBD)
**Concept:** Customers don't want products - they want to accomplish jobs

**The Framework:**
1. **Job Definition:** What underlying job is customer trying to accomplish?
   - Functional job: Task to be done
   - Emotional job: Feeling they want to achieve
   - Social job: How they want to be perceived
2. **Circumstances:** When/where do they need it?
3. **Competing Solutions:** What alternatives exist?
   - Other products
   - DIY solutions
   - Doing nothing
4. **Desired Outcomes:** What success looks like

**Example:** User doesn't want Slack - they want to communicate seamlessly with remote team

**Application:**
- Interview users about their jobs
- Map competing solutions
- Design around the job, not features
- Measure outcome achievement

### Design Thinking
**Process:** Empathy → Define → Ideate → Prototype → Test

**Phase 1: Empathize**
- User research
- Observation
- Interviews
- Empathy mapping
- Goal: Deep understanding of user pain

**Phase 2: Define**
- Synthesize research
- Define the problem
- Problem statement: "How might we...?"
- Create point of view

**Phase 3: Ideate**
- Brainstorm solutions
- Divergent thinking
- Quantity over quality
- Build on ideas
- No criticism phase

**Phase 4: Prototype**
- Low-fidelity first
- Rapid iteration
- Fail fast, learn quickly
- Test-friendly designs

**Phase 5: Test**
- Get user feedback
- Iterate based on learning
- Validate assumptions
- Return to previous phases

### Lean Canvas (One-Page Business Plan)
**Use:** Quick business model for startups/products

**9 Blocks:**
1. **Problem:** Top 3 problems
2. **Customer Segments:** Who are you targeting?
3. **Unique Value Proposition:** Why you're different
4. **Solution:** How you solve the problem
5. **Channels:** How users hear about you
6. **Revenue Streams:** How you make money
7. **Cost Structure:** Main costs
8. **Key Metrics:** What you measure
9. **Unfair Advantage:** Why others can't copy

**How to Use:**
- Lean on assumptions, not data
- Revise as you learn
- Validate each block
- Pivot if needed

### Kano Model (Feature Prioritization)
**Concept:** Different features impact satisfaction differently

**4 Feature Types:**
1. **Must-Haves (Threshold):** Expected baseline
   - If missing: Customer angry
   - If present: Neutral (not satisfied)
   - Example: Email works reliably
2. **Performance (Linear):** More is better
   - More = more satisfied
   - Less = less satisfied
   - Example: Email speed
3. **Delighters (Excitement):** Unexpected features
   - If missing: Neutral
   - If present: Very satisfied
   - Example: Scheduled send
4. **Indifferent:** Don't matter to customer

**Application:**
- Identify feature type
- Prioritize: Must-haves first, then performance, then delighters
- Avoid building indifferent features

### OKRs (Objectives & Key Results)
**Structure:** Direction (Objective) + Measurable outcomes (Key Results)

**Objective:**
- Qualitative
- Inspirational
- Ambitious
- Time-bound (usually quarterly)
- Example: "Become the top-rated communication tool for remote teams"

**Key Results:**
- Specific metrics
- 3-5 per objective
- Achievable but challenging
- Measurable
- Example:
  1. 50,000 new active users (from 10,000)
  2. 90%+ customer satisfaction score
  3. $2M ARR (from $500K)

**Best Practices:**
- Bottom-up + top-down alignment
- Quarterly reviews
- 60-70% achievement is good
- Transparent across org
- Link to company mission

### Product Development Lifecycle

**Stage 1: Discovery**
- Problem validation
- User research
- Market analysis
- Competitive landscape
- Build: Research docs, user insights, problem statement

**Stage 2: Ideation**
- Solution brainstorming
- Concept development
- Rapid prototyping
- Idea evaluation
- Build: Prototypes, concepts, feature lists

**Stage 3: Development**
- Requirements definition
- Design (UX/UI)
- Engineering build
- Quality assurance
- Build: Product, testing, documentation

**Stage 4: Launch**
- Go-to-market strategy
- Marketing/sales prep
- Launch day execution
- User onboarding
- Build: Marketing materials, support docs

**Stage 5: Growth**
- User acquisition
- Retention optimization
- Feature expansion
- Scaling infrastructure
- Measure: Metrics, feedback, retention

**Stage 6: Maturity**
- Market leadership
- Profitability optimization
- Platform expansion
- Adjacent markets
- Measure: Market share, margin, lifetime value

**Stage 7: Decline/Pivot**
- Manage decline
- Migrate users
- Sunset gracefully
- OR pivot to new market
- OR new features (return to growth)

## PRODUCT MANAGEMENT PRINCIPLES

### User-Centric Design
- Start with user problem, not solution
- Validate assumptions with real users
- Iterate based on feedback
- Measure user satisfaction
- Build features people actually want

### Data-Driven Decisions
- Define metrics before building
- Measure impact of changes
- A/B test features
- Use data to inform, not dictate
- Combine data + intuition

### Prioritization Framework (RICE)
**R - Reach:** How many users affected?
**I - Impact:** How much does it help each user?
**C - Confidence:** How confident are you?
**E - Effort:** How much work required?

**Score = (Reach × Impact × Confidence) / Effort**

### MVP (Minimum Viable Product)
- Smallest set of features to test hypothesis
- Validate core value proposition
- Quick to build, get feedback
- Iterate based on learning
- Not about building perfect product

## METRICS & ANALYTICS

### Acquisition Metrics
- **DAU/MAU:** Daily/Monthly Active Users
- **CAC:** Customer Acquisition Cost
- **Conversion Rate:** % who take desired action
- **Signup Rate:** % who sign up
- **Viral Coefficient:** How many new users each user brings

### Engagement Metrics
- **Session Length:** Time spent per session
- **Frequency:** How often users return
- **Feature Adoption:** % using specific features
- **Time to First Action:** Speed to core value
- **Stickiness:** DAU/MAU ratio

### Retention Metrics
- **Churn Rate:** % of users who leave
- **Retention Cohorts:** % retained after X days
- **LTV:** Lifetime Value (total revenue per user)
- **Repeat Purchase Rate:** % who buy again
- **NPS:** Net Promoter Score (would recommend?)

### Revenue Metrics
- **ARPU:** Average Revenue Per User
- **ARPPU:** Average Revenue Per Paying User
- **LTV:CAC Ratio:** Should be 3:1 or better
- **Payback Period:** How long to recover CAC
- **Unit Economics:** Revenue vs cost per unit

## COMMUNICATION & STAKEHOLDERS

### Managing Up (Leadership)
- Speak their language (business impact)
- Lead with outcomes, not features
- Be data-driven
- Recommend clearly
- Acknowledge constraints

### Working with Engineering
- Be clear on requirements
- Prioritize ruthlessly
- Understand technical constraints
- Respect engineering input
- Celebrate wins together

### Collaborating with Design
- Share user research
- Design for outcomes, not aesthetics
- Iterate together
- Get feedback early
- Trust designer expertise

### Understanding Sales
- Listen to customer feedback
- Create materials they need
- Incorporate competitive intel
- Support deal closure
- Track win/loss analysis

## COMMON PM MISTAKES

1. **Building without validating:** Assuming you know the problem
2. **Feature creep:** Adding features without prioritization
3. **Ignoring data:** Making decisions on gut feeling alone
4. **Poor communication:** Not aligned with stakeholders
5. **No roadmap:** Reacting instead of planning
6. **Slow iteration:** Taking too long to launch
7. **Wrong metrics:** Measuring vanity metrics instead of impact
8. **Ignoring competition:** Not aware of alternatives
9. **User neglect:** Not talking to actual users
10. **Scope creep:** MVP becoming bloated

- **Market position:** Where do we sit?

2. **3 Key initiatives:** Top priorities
3. **Success metrics:** How we measure
4. **Timeline:** Phases and milestones
5. **Resources needed:** Team, budget, tools
